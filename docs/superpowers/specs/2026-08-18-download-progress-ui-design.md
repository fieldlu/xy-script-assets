# 下载进度界面紧凑化设计

日期：2026-08-18
版本约束：保持脚本版本 3.6.4，不发布 3.6.5

## 背景

当前下载进度区域把批量计数、完整文件名、文件百分比和操作按钮放在同一行。下载大文件且文件名较长时，文本会超出下载面板宽度，造成布局拥挤和按钮错位。

## 目标

- 让下载进度区域在约 290px 的下载面板宽度内稳定显示。
- 长文件名不再撑破布局，使用省略号截断，并保留完整文件名供悬停查看。
- 将批量进度、当前文件、文件接收量和操作按钮分层展示。
- 保持现有下载链路、暂停、终止、成功/失败计数逻辑不变。
- 保持版本号为 3.6.4。

## 方案

将现有进度区域改成紧凑卡片式布局：

1. 第一行显示下载状态、批量计数和百分比。
2. 第二行显示当前文件名，使用 `min-width: 0`、`overflow: hidden`、`text-overflow: ellipsis` 防止溢出，并通过 `title` 保留完整名称。
3. 第三行显示固定高度的进度条。
4. 第四行左侧显示“已接收”字节数，右侧显示暂停/终止按钮。
5. 操作按钮固定不收缩；窄宽度下通过紧凑文字和固定 padding 保持可用。
6. 进度文本由 JavaScript 分别写入状态、文件名、字节数和百分比节点，不再拼接成一个超长字符串。

## 交互与兼容性

- 无法取得总大小时，仍显示已接收字节数，不显示虚假的文件百分比。
- 能取得 `Content-Length` 或 `Content-Range` 时显示“已接收 / 总大小”。
- 完成、失败、终止时沿用现有批量计数和提示逻辑。
- 不改动 `quote_id → file_url → Authorization fetch → ReadableStream → Blob → a.click()` 下载链路。

## 验收标准

- 进度区域在 290px 左右宽度下无横向溢出。
- 长文件名显示省略号，不覆盖百分比、按钮或进度条。
- 暂停、终止、全选、清空按钮均可点击。
- 现有下载回归测试继续通过，并新增进度 DOM/文本分层断言。
- 脚本及配套元数据版本均保持 3.6.4。
